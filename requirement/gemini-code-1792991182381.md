## 🛑 Global Instructions & Coding Standards for the AI Agent

### Project Metadata
* **Repository Name:** `tdb-vazhipadu-frontend`
* **GitHub Account Handle:** `emmanualceaser1234`
* **Stack:** React 18+, TypeScript (Strict Mode), Vite, Tailwind CSS, Lucide Icons, React Router v6+, Vitest, React Testing Library.
* **Time Budget Strategy:** Execution must be fast, highly modular, and disciplined.

### Core Architectural Standards
1. **TypeScript Strictness:** No `any`, `unknown` without explicit narrowing, or non-null assertions (`!`). All types must be fully defined under `src/types/`.
2. **State Management:**
   * Global/Cart State: Synced to `localStorage` via custom hooks with defensive error handling (JSON schema parsing/fallback).
   * Form State: Fully typed with controlled inputs and real-time validation.
   * UI State (Filters/Pagination): Deeply synchronized with URL Search Parameters (`useSearchParams`) so state persists on page refresh.
3. **Data Fetching & Resiliency:**
   * Custom hook or light query wrapper around mock API calls to seamlessly handle loading states, transient network errors, full retry mechanisms, and idempotency keys to prevent duplicate submission.
4. **Accessibility (a11y) First:**
   * Semantic HTML layout elements (`<header>`, `<main>`, `<footer>`, `<section>`, `<nav>`).
   * Explicit `<label htmlFor="...">` bindings for every form input.
   * `aria-live="polite"` regions for screen-reader error announcements and status changes.
   * High-contrast Tailwind palette (`slate-900`, `emerald-700`, `indigo-700`, etc.) meeting WCAG AAA standard.
   * Full keyboard focus management (`tabIndex`, focus rings `focus-visible:ring-2`).
5. **Git & PR Workflow Strict Rules:**
   * Do NOT commit directly to `main`.
   * Create single feature branches per problem (`feature/p1-offerings-list`, `feature/p2-cart-and-form`, etc.).
   * Make small, granular commits with standard semantic messages (e.g., `feat(api): add typed mock storage with failure rate`, `test(offerings): add search filter unit test`).
   * PRs MUST contain a populated description matching the required template, include simulated PR inline review comments, and be merged cleanly via Squash/Merge into `main` before starting the next branch.

## 🏁 Phase 0: Project Initialization & Mock API Core Setup

### Objective
Set up Vite + React + TypeScript + Tailwind + Vitest baseline, and establish the robust in-memory typed Mock API with storage persistence.

### Detailed Requirements
1. **Vite Baseline Setup:**
   * Initialize React + TypeScript template.
   * Install and configure Tailwind CSS and `lucide-react`.
   * Configure Vitest + React Testing Library + `@testing-library/user-event` + `@testing-library/jest-dom`.
2. **Mock API Module (`src/api/`):**
   * **Types (`src/types/vazhipadu.ts`):**
     * `Temple`: `id`, `name`, `code`, `location`, `description`.
     * `Offering`: `id`, `templeId`, `name`, `description`, `priceRupees`, `isActive`, `category`.
     * `Nakshatra`: Union type of all 27 birth stars (Ashwathi, Bharani, Karthika, ..., Revathi).
     * `OrderStatus`: `'PENDING' | 'CONFIRMED' | 'CANCELLED'`.
     * `OfferingItem`: `offeringId`, `offeringName`, `priceRupees`, `quantity`, `devoteeName`, `nakshatra`, `date`.
     * `Order`: `id`, `orderNumber` (e.g., `TDB-20261026-XXXX`), `templeId`, `devoteeName`, `phone`, `nakshatra`, `offeringDate`, `items` (Array of line items), `totalAmount`, `status`, `createdAt`.
   * **Data Seeding (`src/api/seedData.ts`):**
     * At least **2 Temples** (e.g., *Sree Sabarimala Sastha Temple*, *Chottanikara Devi Temple*).
     * At least **10 offerings per temple** (e.g., Pushpanjali ₹30, Archana ₹50, Ganapathy Homam ₹150, Swayamvara Pushpanjali ₹100, Payasam Neivedyam ₹80, Neeranjanam ₹120, etc.). Include a mix of `isActive: true` and `isActive: false`.
     * At least **50 existing orders** across various dates, statuses (`CONFIRMED`, `CANCELLED`), and phone numbers for filtering/pagination tests.
   * **In-Memory Store Mechanics (`src/api/mockClient.ts`):**
     * Load initial seed into `localStorage` if not present, enabling persistent mutations across refreshes.
     * Simulated delay: `Math.floor(Math.random() * 800) + 200` ms.
     * Configurable Failure Rate: Default 10% probability (`Math.random() < 0.1`). Throw `ApiError` with clear message when triggered.
     * Exported Typed Functions:
       * `getTemples(): Promise<Temple[]>`
       * `getOfferings(templeId: string): Promise<Offering[]>`
       * `createOrder(request: CreateOrderDTO): Promise<Order>` (Generates unique order number and validates input)
       * `getOrders(query: GetOrdersQuery): Promise<PaginatedResult<Order>>` (Supports status filter, date range filter, phone number search, and page/limit)
       * `cancelOrder(orderId: string): Promise<Order>` (Updates status to `CANCELLED`)
